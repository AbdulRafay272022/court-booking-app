## 3. Endpoints
- `GET /owners/venues/{venue_id}/timers` -> `VenueTimers { values: {hold_minutes|null, reminders_enabled|null, first_reminder_after_min|null, repeat_every_min|null, max_reminders|null, auto_cancel_enabled|null, auto_cancel_after_min|null}, defaults: {...same keys, non-null}, effective: {...non-null} }`. `PUT` same path body = `values` (null resets to default) -> `VenueTimers`. Owner only (or staff with edit_venue_settings permission, whichever exists). Validation errors 422 with field + Roman Urdu-friendly code `TIMER_OUT_OF_RANGE`.
- Enforcement: hold uses effective hold_minutes; owner reminders + final warning + auto-cancel use the venue's effective values through `reminder_schedule`, only during venue operating hours (`shift_to_open_hours`), deduped via notification_log (`payment_reminder_<n>`, `payment_final_warning`), stop when owner acts or player cancels. auto_cancel_enabled=false -> never auto-cancel (slot stays held). The existing escalation WhatsApp/SMS ladder is REPLACED by these reminders (channel: existing owner channels via `_send_push_and_whatsapp` with bell=True).
- `GET /owners/me/permissions` -> `{ role: "owner"|"staff"|"admin", venue_permissions: [{venue_id, permissions: string[]}] }` (owners/admin get every permission key for their venues).
- Identity (CNIC): `GET /owners/identity` -> `{status: "missing"|"submitted"|"verified", masked: "*****-*******-1"|null, flags: string[]}` (never the number); `POST /owners/identity` multipart `number`, `front`, `back` (replace allowed) -> same shape; 422 `CNIC_INVALID` (13 digits after removing dashes), image validation as other uploads. Admin: `GET /admin/owner-identities?filter=missing|duplicates|unverified|all&page` (masked only + owner name/phone last4 + flags); `GET /admin/owner-identities/{user_id}` (FULL number + short-lived signed photo URLs; writes audit_log `owner_identity.viewed` every call); `POST /admin/owner-identities/{user_id}/verify`. Duplicate cnic_hash under another user adds flag `duplicate_cnic` to both rows (never blocks).
- Web Push per `docs/web-push-plan.md` section 4 (`GET /users/me/web-push/config`, `POST`/`DELETE /users/me/web-push`, `GET /users/me/web-push?endpoint=`), sender + log channel `web_push` + cleanup job runner name `webpush-clean`.
- Notification payload: new log rows carry `payload` (small JSON: amounts, counts, names already shown to that user; never phone/CNIC); the feed uses payload when reference resolution is empty (daily digest numbers, premium, marketing).
- Duplicate screenshot: approve body gains `confirm_duplicate: bool`; approving a payment with `is_duplicate=true` without it -> 409 `DUPLICATE_PROOF_CONFIRM_REQUIRED` details `{used_on_bookings: N}`. `ApprovalQueueItem` gains `duplicate: {used_on_bookings: number} | null`.
- No-show fix: expiry job NO LONGER moves booked -> no_show. Completion (Haan/Nahi) sets booking status `completed` (from booked OR no_show). Manual no-show: existing `POST /bookings/{id}/no-show` allowed after the slot ended for owner / staff with checkin permission, now also from... booked only, with audit. Row gains `status_pending: bool` (= booked AND slot ended AND not completed/no_show). Overview gains `status_pending_count`; History status filter value `status_pending`. Owner daily digest gains the line "N bookings ka status baqi hai" when N>0.
- Public stats: bookings = booked + completed + no_show on live venues.

## 5. Backend as built (agent BE): additions and deviations
Migration revision `e5b8c2d4f6a1` (down_revision `c4f1a9e2d7b3`). Everything below is additive.
- Timers endpoints: owner, admin, or staff with `edit_court_settings` (no `edit_venue_settings` key exists); GET is also allowed (read-only) for staff with `view_ledger`; any other staff 403 `NOT_STAFF_PERMITTED`. `/owners/me/permissions` lists `edit_court_settings` like every other key. 422 `TIMER_OUT_OF_RANGE` details `{field, errors: [{field, code, min, max}]}`. A PUT that changes auto-cancel re-times screenshots already waiting (from each one's own submission time).
- Reminder timing: submission time = the pending payment's `created_at`. When several steps are due at once (late run / morning after a night) only the LATEST goes out. Reminders disabled = no numbered reminders, but the final warning still goes when auto-cancel is on (same rule as `reminderSchedule` with max 0). The auto-cancel itself is NOT moved by night shifting (keeps today's behaviour); a final warning that would shift past the cancel is simply never sent. Venue hours for shifting = earliest open / latest close across the venue's active courts for that weekday.
- Feed kinds ADDED: `payment_reminder` (event `payment_reminder_<n>`), `payment_final_warning`, `payment_auto_cancelled` (event `owner_payment_auto_cancelled`), all link `approvals`. TS updated (`round2.ts` NotificationKind, `notification-text.ts` TITLES). Feed `params` gained optional `count`, `status_pending`, `reminder_no`, `minutes_waiting`, `minutes_to_cancel`, `title` (filled from `notification_log.payload`; resolved values win).
- Auto-cancel with a screenshot on file: the owner gets `owner_payment_auto_cancelled` (push + WhatsApp + bell: "if the money arrived it has to go back"). NO refund row is created automatically (the screenshot is unverified money); the expired card in Approvals -> "Paisa aa gaya" creates the refund-owed row through the existing acknowledge/dispute path. Without a screenshot the owner gets `booking_cancelled` as before.
- `OwnerRefundOut` gains `duplicate_proof: {used_on_bookings} | null` (lead request, findings 1). `used_on_bookings` counts OTHER bookings where a payment of the same image group (duplicate_of chain, identical proof_hash, same OCR reference; ANY player) was approved. `is_duplicate` itself already compares across players.
- Approve with `is_duplicate=true` and no `confirm_duplicate` -> 409 even when `used_on_bookings` is 0 (the original was rejected). Reject never needs the confirm.
- Manual no-show: allowed only once the slot has ENDED (was start + 60 min; same code `TOO_EARLY_FOR_NO_SHOW`), owner or staff with `check_in` OR `record_payments`. Completion (Haan/Nahi) keeps its `record_payments` permission. Completing a `no_show` gives the player's no-show count back.
- `status_pending` = status `booked` AND ended AND no Haan/Nahi audit row (a completion made before Stage 2 left status `booked` but is not pending).
- CNIC: masked shows only the check digit (`*****-*******-3`); photo errors are 400 `INVALID_IMAGE_FORMAT` / `PROOF_TOO_LARGE` like other uploads; blank `CNIC_HASH_KEY` with DEBUG=false -> 503 `CNIC_NOT_CONFIGURED`; replacing resets verification. Admin list page size is fixed at 50; `submitted_at` = the row's last update.
- Web Push subscribe with a non-allowed endpoint -> 422 `WEB_PUSH_ENDPOINT_NOT_ALLOWED`. Cron line `webpush-clean` daily 04:00 PKT.
